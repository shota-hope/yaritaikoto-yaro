## 合意済みの方針

- シンプルなUIと少ない入力を重視する。健康寿命を特徴として押し出し、次の一歩につなげる。
- 初回は年齢のみを必須入力とし、入力後に時間の目安を表示する。ログイン・生年月日・統計の区分は初回に求めない。
- スマートフォンでの表示・操作を最優先に設計する。
- 時期の選択肢は「今月／今年／未定」。初期値は「未定」とし、後から編集できる。
- リストはデフォルト1つ。複数リストの追加は将来機能とする。
- リストはデフォルト非公開。匿名公開、他の人のやりたいことの閲覧、リストの公開URLは将来機能とする。
- リポジトリ名は `yaritaikoto-yaro`。

## レビューするアウトカム案

「やりたいことを1つ選び、次に何をするかが決まる」。利用後に、その一歩を実際に行えたかを確かめる。これは会話で提案した評価軸で、最終的な成功条件はレビューで決める。

GitHubリポジトリ名: `yaritaikoto-yaro`。

## 1. 目的

やりたいことを思い出す → 次の一歩を決める → 動き出す時期を決める → 実際にやる → 達成を残す。

残り時間を意識し、やりたいことをリストにして、一つずつ実行していく。健康寿命をもとにした時間の表示は、その行動を後押しする目安としてホーム上部に置く。シンプルなUIと少ない入力で、すぐにリストへ追加できることを重視する。初期版は非公開・個人用。匿名公開とリストの公開URLは将来機能として扱う。ランキング、スコア、ストリーク、AI助言、行動ログ解析は初期版に含めない。

## 2. 初回体験と画面

- 独立した年齢入力画面を設けず、アプリ名、年齢入力と残り時間、健康寿命の短い説明、その直下の追加欄・リストを同じ画面にまとめる。
- 必須入力は年齢の1項目のみ。入力すると健康寿命の目安までの時間が分かる。入力済みの年齢は保存し、再訪時には再入力を求めない。年齢未入力でも追加欄と空のリストを表示し、追加実行時に年齢入力を案内して入力中のタイトルを保持する。
- 「やりたいことやろう」はアプリ名として明確に表示する。ポップなロゴや装飾を避け、普通の文字組み、白・黒・グレー、薄い罫線を中心としたシンプルな見た目にする。
- 大きな余白や説明用の大きな見出しを避ける。追加用の入力欄を常時表示し、その下にリストを置いてすぐに追加できるようにする。文字の読みやすさとタップ領域は保つ。
- タイトルだけで追加可能。次の一歩は任意。時期の初期値は「未定」。追加時に時期の選択を求めず、後から編集できる。
- 初期版のやりたいことリストは1つのみ。リストの追加・切り替えUIは設けない。デフォルトの名称例は「動けるうちにやりたいことリスト」で、正式な表示名は未定。
- ホームのカードに次の一歩を表示する。
- 編集はカード内にインラインで開く。タイトル、次の一歩、動き出す時期、削除を扱う。スマートフォンで大きな下部シートを重ねず、一画面で完結させる。
- 各項目の左に直径36pxの達成アイコンを置き、44px以上の操作領域を確保する。押すと達成になり、もう一度押すと取り消せる。
- 達成した項目は別一覧へ移動せず、元の位置に達成日とともに表示する。
- 設定はGoogle連携、年齢・生年月日・統計の区分、エクスポート、全データ削除、出典と注意書き。
- Googleログイン直後のプロフィール入力モーダルは作らず、設定から任意入力する。

### スマートフォン優先の画面設計

- スマートフォンの縦画面を基準に、時間の目安・追加操作・リストを読みやすく配置する。PC・タブレット表示はその体験を広い画面に合わせて調整する。
- 基本は1カラムとし、横スクロールを必要としない。文字や操作部品を小さく詰め込まない。
- タップ操作を前提にする。年齢入力には数字キーボードを使える入力欄を用意する。
- 編集UIはスマートフォンで入力しやすい構成とし、ソフトウェアキーボード表示時にも入力欄・保存操作を扱えるようにする。
- 小さい画面、文字拡大、実機での入力・編集を確認する。

## 3. 「いつ動き出す？」

選択肢は **今月／今年／未定**。

初期値は「未定」。タイトルだけで保存でき、後から編集画面で時期を設定・変更できる。設定済みの時期を「未定」に戻すこともできる。

これはやりたいこと全体の完成期限ではなく、現在の「次の一歩」に取りかかる時期。次の一歩が空欄なら、やりたいことに最初に着手する時期を表す。実現日を別途入力する機能はMVPには追加しない。

以下の暦の扱い、一歩を更新したときの時期リセット、既存プロフィールの優先順位は、実装用に補った初期案。会話で個別に確定した要件とは区別する。

実装上の暦の扱い:

| 選択肢 | 保存する action_due_on |
| --- | --- |
| 今月 | 選択時点の月末 |
| 今年 | 選択時点の12月31日 |
| 未定 | null |

- Asia/Tokyoの暦日を使い、選択時に絶対日付へ変換して保存する。期限当日は超過扱いにしない。
- 一覧は保存済み日付を今日から見て「今月」「今年」「未定」に分類する。重複時は最も近い区分に入れる。
- 過ぎたものは「予定を見直す」にまとめる。赤い警告やペナルティを出さない。
- 時期を再選択したときだけ日付を更新する。タイトルの編集だけでは延長しない。
- 「やった、次を書く」は現在の一歩の完了と次の一歩への置き換え。新しい一歩の時期は未定へ戻して再選択できる。やりたいこと全体の達成とは別操作。
- 「達成にする」はstatusとdone_onを更新する。取り消し時はdone_onを空にする。

## 4. 時間を考える目安

- 残り時間は「約○年○日」と表示する。保存日時の東京暦日から目安日を求め、今日から目安日までの満年数と端数日へ分ける。2月29日から年を加算して非うるう年になる場合は2月末へ丸める。
- 表示名は「時間を考える目安」。初回に入力した年齢をもとに、ホームで時間の目安を表示する。目安を超える場合の表示は下記の方針に従う。
- 2022年の健康寿命の値として男性72.57年、女性75.45年を使用する計画。区分未選択時はアプリが採用した中間値74.01年を使い、公式の男女合計値とは表現しない。
- 出典、公表日、採用値は1ファイルにまとめ、実装時に数値と出典の対応を確認する。
- 年齢のみの場合は入力日時点の年齢から半年前を誕生日の仮置きとして計算。推定であることを保存する。
- 生年月日を入力しても表示の「約」は残す。日付の計算精度と健康状態の予測精度を混同しない。
- 数字の近くに「個人の寿命や健康状態を予測するものではありません」と表示する。
- 目安を超えたら日数を隠し「これから、何をしたい？」と表示。マイナス日数や健康状態の断定はしない。
- 健康寿命の値からやりたいことの期限は自動設定しない。
- 月末・うるう年・2月29日生まれの扱いはcoreで定義し、テストする。

出典: https://www.mhlw.go.jp/content/10904750/001363070.pdf

## 5. 保存・ログイン

- 最初の試作は端末内に保存し、再読み込み後も継続利用できるようにする。
- 本体では初回の年齢入力を保存するときに匿名セッションを生成し、サーバーに保存する。入力途中や閲覧だけでは生成しない。
- 初回保存後に一度だけ「このブラウザで続けられます。Google連携すると、別の端末でも開けます」と案内する。
- 設定にはCookie削除や匿名セッション喪失後にデータを取り出せなくなる場合があることを明記する。
- Google連携のバナーは3件目の追加または初達成の早い方。一度閉じたら再表示しない。設定から常に連携可能。
- 新規Google・既存Googleの双方について匿名データの移行を検証する。同じユーザーIDが維持されることを前提にしない。
- 既存アカウントのプロフィールを優先し、空欄のみゲスト値で補う。やりたいことはIDを保持して移行する。
- 移行成功前に匿名データを削除しない。失敗後の再試行で欠損や重複が起きない設計にする。
- ログアウト、アカウント切り替え、全削除時は利用者ごとの読み取りキャッシュも破棄する。
- JSONエクスポートと全データ削除はゲストにも提供する。

認証仕様の参照: https://better-auth.com/docs/plugins/anonymous

## 6. 技術構成

- Vite + React + TypeScript + Tailwind、PWA。
- Cloudflare Workers + Static Assets、Hono、D1、Drizzle。
- Better AuthのGoogleプロバイダとanonymous plugin。
- core/（純粋TypeScriptの日付・分類ロジック）、web/、worker/のpnpm workspace。
- サーバー状態はTanStack Query。オフラインは読み取りのみ。本体の書き込みには接続が必要。
- 無料枠内での運用を目指す。月額0円は保証せず、認証を含め実測する。
- 独自ドメインは後回し。workers.devから開始する。
- 通知、ネイティブアプリ、ウィジェット、年別振り返りは後続候補。

Workers制限の参照: https://developers.cloudflare.com/workers/platform/limits/

## 7. データモデルの変更点

- Better Auth管理テーブルは採用バージョンの必要スキーマに合わせる。
- wishesはid、user_id、title、next_step、action_due_on、status、done_on、created_at、updated_atを持つ。
- 元案のtimeframeとdue_onを起点とする長期期限は廃止。action_due_onを分類の基準にし、期限なしはnullとする。
- 日付はYYYY-MM-DD。日時は別途統一形式を定義し、日付と混同しない。
- APIの各読み書きはセッションの所有者に限定する。
- 元案のme、export、wishes、authのAPI構成は維持する。

## 8. 実装・検証順

1. GitHubリポジトリと開発雛形を用意する。公開範囲未指定のため、初期作成はPrivateを既定とする。
2. coreの日付変換・グループ分類を実装し、月末・年末などの境界を検証する。
3. 端末内保存でホーム、追加、次の一歩、達成までの試作を作る。
4. Workersで匿名保存、Googleログイン、移行を小さく検証し、無料枠のCPU時間を実測する。
5. 本体APIを接続し、設定、エクスポート、削除、利用者切り替えを仕上げる。
6. スマートフォンを優先し、初回の年齢入力から時間の目安表示、追加・編集・達成までPWAとして実機で確認する。小さい画面やキーボード表示中の操作、書き込み失敗時に保存成功と表示しないことも検証する。
7. 自分で2週間使用し、「次の一歩を実行できたか」「予定を具体化できたか」で評価する。

## 9. 将来機能（MVPには含めない）

### 複数リスト

- 最初から用意するリストは1つ。利用開始時にリスト作成や分類を求めない。
- 必要な人だけ、やりたいことリストを追加できるようにする。
- 追加するリストもデフォルト非公開とする。
- 1つのリストだけで使い続けられるシンプルさを保つ。
- リスト名、並べ替え、項目の移動・複数所属などの詳細は、この機能に着手するときに決める。初期版の入力項目は増やさない。

### 匿名公開・公開URL

- やりたいことを匿名で公開し、他の人が公開したやりたいことを見られるようにする。
- リスト自体もデフォルト非公開とし、希望する人が公開URLを発行できるようにする。
- 匿名公開の一覧への掲載と、リストのURL共有は別の操作として設計する案。URLの公開範囲、公開項目、公開停止の扱いは機能設計時に詰める。
- 年齢・生年月日・健康寿命の表示などのプロフィール情報は、リスト共有で自動公開しない方針案とする。

### やりたくないことリスト

- 初期版には含めず、将来、希望する人が「やりたくないことリスト」を追加できるようにする。初期状態では作成しない。
- 仕事・通勤・気の進まない付き合いなど、減らしたい負担を記録する用途を想定する。追加するリストはデフォルト非公開とする。
- 以前の「将来の実装予定にも含めない」という見送り方針を変更する。
- 「やらなくてよくなった」「減らせた」変化の可視化は検討案として残す。完了状態、次の一歩、振り返り、公開範囲などの詳細は、この機能に着手するときに決める。
- 初期版でも「仕事を減らしたい」などは、通常のやりたいこととしてそのまま登録できる。
